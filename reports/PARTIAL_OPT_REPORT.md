## 1. Task 1 — VRAM 규명 (안전, 단독 선보고 완료)

`VRAM_AUDIT.md` 참조. 핵심:
- 프로세스별 VRAM은 Windows WDDM에서 `[N/A]` → `ollama ps` + 격리 로드로 산출.
- v1의 ~11.7GB는 **GPU 전체**(Ollama 10.1GB + 데스크톱 1.45GB)였고, `qwen2.5:14b`가 **미언로드 상주**(keep_alive 2h, CPU 15% 오프로딩)한 결함이 겹침. → **측정오류 + 상주결함 병존**.
- 격리 실측: EXAONE **6792MB**, qwen2.5:14b **10140MB**, 데스크톱 **1450MB**, 실가용 **≈10832MB**. 동시상주(16932MB) 불가 → 순차 로드 필수.
- **조치(결함 수정)**: 요약(EXAONE) 종료 시(실호출 있었을 때만) 언로드, 브리핑(qwen) 종료 시 언로드. 실행 후 `ollama ps` 공백·VRAM 데스크톱 수준 회수 검증 완료. `UNLOAD_MODELS=1` 기본.

## 2. Task 2 — 계측 교정

- **실측 토큰**: 문자수 폐기, Ollama `usage`(prompt_eval/eval)로 `prompt_tokens`/`output_tokens` 기록. `schema_ver=2`로 v1과 분리.
- **캐시/실호출 분리**: 요약 집계를 `cache_hit=0`(실 LLM 호출)과 캐시 반환으로 이원화. 평균 응답은 실호출만.
- **⚠️ 오버헤드 결함 시정(중대)**: `log_llm`이 매 호출마다 sqlite 연결+스키마+마이그레이션을 재수행 → 요약 단계가 **38s로 부풀려짐**(계측 오버헤드 52%, §0.1 "2% 이내" 위반). 연결 1회 재사용으로 수정 → 요약 단계 **0.04s**. **v1/v2 초기 수치는 이 오버헤드로 오염되었던 것**이 규명됨.

## 5. Task 4 — num_ctx 적정화 (원복)

| 조건 | 요약단계(s) | 건당응답(s) | 요약 피크VRAM(MB) |
| --- | ---: | ---: | ---: |
| 기본(미설정) | 141.3 | 1.39 | 8308 |
| num_ctx=512 | 145.4 | 1.43 | 8393 |

- 콜드 요약 prompt_tokens 분포: p50=175, **p95=280**, max=1366 → 권장 512(=ceil(p95×1.25)).
- 결과: **개선 없음**. Δ요약 -4.1s(콜드 편차 3.2s를 겨우 상회하는 노이즈), VRAM -85MB(악화). 입력이 작아 기본 컨텍스트로 충분하고, max=1366이 512를 초과해 상향 가드가 발동.
- **판정: 원복**(SUMMARY_NUM_CTX 미설정 유지). "안 되는 걸 확인"한 기록. 초과입력 상향 재시도 가드는 코드에 유지(조용한 잘림 방지).
